> If you are comfortable with it, you can use it as an interactive login shell, and you can use it to write cross-platform scripts, albeit PowerShell Core on Linux won't support the features that really make PowerShell useful on Windows - Active Directory integration and integration with policies and other system and network management features.
> 
> PowerShell cmdlets also have an object-based pipeline architecture which is more structured than the Unix model involving arbitrary I/O. It's more like an API, and some people prefer that to scraping output because objects are more intentional than output that might have been designed to be human-readable, not ingested with a tool.
> 
> But APIs can change just as easily as interfaces, so it may be more of a subjective preference, and the objects can get big and complicated and that can present its own barrier to human-readability. My personal preference is that PowerShell is a better shell than the legacy Windows/DOS command interpreters, but that it's not better than any of the modern Unix-style shells.
> 
> On Unix-style systems, we're seeing "porcelain" interfaces (like git) and json interfaces becoming more popular and standard, so we're not really missing out without PowerShell.
